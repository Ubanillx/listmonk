# Harness 工程台账

本目录用于记录持续开发所需的任务、计划、状态、技术债、技术架构和业务逻辑。内容面向贡献者和自动化编码代理，不替代面向用户的产品文档。

## 文档索引

| 文件 | 用途 |
| --- | --- |
| [TODO.md](TODO.md) | 当前代码中已确认、尚未完成的事项。 |
| [PLAN.md](PLAN.md) | 已排定或建议排定的后续工作。 |
| [STATUS.md](STATUS.md) | 已完成与未完成情况的快照。 |
| [TECH_DEBT.md](TECH_DEBT.md) | 已知技术债、影响、优先级和偿还策略。 |
| [TECH_ARCHITECTURE.md](TECH_ARCHITECTURE.md) | 技术架构入口和模块边界。 |
| [BUSINESS_LOGIC.md](BUSINESS_LOGIC.md) | 核心业务流程和不变量。 |

## 维护规则

- 每次代码、配置、脚本或权限行为变更，都在同一变更中更新受影响的台账。
- `docs/ARCHITECTURE.md` 是系统架构、技术栈、权限算法和部署命令的权威文档；本目录只做索引和执行状态记录。
- TODO、计划和技术债必须写明来源、责任范围、验收条件或下一步，不使用无来源的泛化描述。
- 完成事项移入 `STATUS.md` 的“已完成”，并从 `TODO.md` 删除或标记为已关闭。
- 状态快照发生变化时更新文档顶部的日期。
