- 技术债清理批次 8：回信转发的失败重试（2026-09-10）。由子代理实施、由本机独立复跑验收。原实现把去重插入写成 `ON CONFLICT DO NOTHING ... RETURNING id`：首次发送失败后行被置为 `failed`，下一轮同 key 命中既有行、`RETURNING` 无结果即 `return nil`，且全仓没有任何消费者读 `failed`/陈旧 `pending` 行——队列拥塞、SMTP 瞬时故障或 reload 会让客户回复**永久不转发**，只在数据库留痕。现把去重门改为原子 **claim**：单条 `INSERT ... ON CONFLICT (rule_id, message_key) DO UPDATE SET status='pending', attempts=attempts+1 ... WHERE (status='failed' AND attempts < 上限 AND 退避已过) OR (status='pending' AND 领取已过期租约) RETURNING id, attempts`，无返回即跳过（已转发／仍有在途领取／已耗尽）。选择「把扫描本身作为重试器」而非独立 worker：原始邮件正文不落库，独立 worker 必须为每条规则重开 POP3 并重新枚举邮箱才能按 key 找回正文，等于复制一遍扫描；而扫描本就每 60 秒重读每个源邮件（源邮件从不删除）。策略：最多 5 次尝试，退避 1m→16m 指数增长，领取租约 5m；耗尽后停在 `failed` + attempts 达上限 + `last_error`，配有结束日志。**无需迁移**：`status`/`attempts`/`last_error`/`updated_at` 均已存在（v6.15.0），在途 = `pending` + 新鲜 `updated_at`，终态 = `failed` + attempts 达上限；旧数据也能恢复（旧 `failed` 行在退避后重试、旧崩溃遗留的 `pending` 在租约后接管、`forwarded` 永不重领）。防重发顺序：①先提交 claim 再发送，并发扫描在行锁上重判 `DO UPDATE ... WHERE` 得到零行；②`forwarded` 只在 `PushMessage` 返回 nil 后写入且任何分支都不会再选中它；③行变为 `failed` 的前提是 `PushMessage` 报错，而报错意味着消息从未进入 `m.msgQ`（未发送）；④租约 5m 远大于 `PushMessage` 最长 3s 阻塞，故租约过期即持有者已死；结果更新以 `status='pending' AND attempts=$n` 做围栏。**如实记录的残余窗口**：进程在 `PushMessage` 已接收消息、成功 UPDATE 尚未提交时崩溃 → 行仍是 `pending`，租约后被重发一次（至少一次语义，宽度约一次数据库往返；除非收信 MTA 提供幂等键，否则无法完全关闭；修复前同一窗口会静默丢件，两害相权取重复投递）。新增 `cmd/reply_forwarder_test.go` 5 项（4 项数据库门控，用一次性库 `newAdminTestDB`，不触碰 dev 的 `public`；投递通过替换 manager 的 messenger 为录制桩来计数）：首推失败 → `failed`/attempts=1/forward_count=0/零投递，退避期内重试不动作，退避后成功转发并落到 `forwarded`/attempts=2/forward_count=1（含主题、Reply-To、`X-Listmonk-Forwarded-Reply` 与原文附件）；成功后连续 5 轮不再重复投递（同邮箱另一封仍正常转发）；尝试次数 1→2→3 后停止并可由「`status='failed' AND attempts >= 上限`」查询定位；在途行（领取未过期）不被抢占、租约过期后被接管并成功转发；策略边界单测。**本机复跑：5/5 PASS（真实 PostgreSQL，`ADMIN_AUTH_TEST_DSN`）。**作者还用两处变异证明测试有效：还原修复前行为 → 重试用例与上限用例 FAIL；允许重领 `forwarded` → 重复投递用例 FAIL（`forwarded 5 times, want exactly 1`）。未验证（如实记录）：POP3 传输层本身未被测试覆盖（该转发器固定 `TLSEnabled: true` 且无 TLS 配置注入点，测试直接驱动 `forwardOneReply`，即扫描对每封邮件调用的同一函数）；worker 层真实 SMTP 失败对转发器仍不可见（`PushMessage` 只入队，属既有行为，需要 `internal/manager` 提供投递结果回调）。移除债务：回信转发的瞬时发送失败被去重表永久吞掉（中高）。来源：`cmd/reply_forwarder.go`、`cmd/reply_forwarder_test.go`、`schema.sql`、`docs/ARCHITECTURE.md`。
