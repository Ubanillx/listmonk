# 部门公海列表权限修复（2026-11-05）

用户要求：公海客户列表只展示当前所在部门实际获分配的列表。

复现：`TestPoolListsStayWithinAllocatedWorkspace` 构造两个组织、同源跨组织分配、其他组织独占公海、仅投放授权及已解除分配。修复前本部门预期 2 行，普通账号得到 5 行，平台权限账号最多得到 8 行；直接详情也能读取未分配列表。

修复：组织空间只返回当前组织未解除的分配及对应一级公海。投放授权不等同于查看分配，主数据/投放/跨组织分配/全组织发送权限和最高管理员身份不扩大该目录。完整目录、minimal 选择器、直接详情、客户数和退订人数使用同一组织边界；单池/汇总联系人、筛选候选、分配目录和 Excel 导出同样受限。停用但仍绑定的分配保留可见。个人空间显式平台管理与专用跨组织分配工作台保留独立授权。

界面：组织空间隐藏全部组织/全局公海/其他组织筛选器，改用顶部工作区切换；保留本部门的来源与分配层级。桌面表格名称列设最小宽度，避免权限收敛后少量记录时被其他列挤窄。

## 独立代码质量 QA

两位独立 agent 分别从仓库规范与需求/权限正确性审查，主 agent 逐项复现并修复：

- **P1，跨部门附加信息**：同一联系人属于两个部门时，最高管理员在部门空间获取单池客户，明文响应的 `exclusions` 曾附带另一部门组织名、移除原因和来源。新增共享联系人回归先失败；附加查询改用与客户状态一致的组织边界，个人空间来源池全局概览保留，分配页只返回目标组织。
- **P2，转移中旁路读取**：目录/详情排除待转移对象，但客户/导出/汇总/筛选未统一检查。提取 `poolAllocationReadPredicate`，同时验证来源和分配列表、未解除状态及两侧待转移标记，所有部门读取入口共用；源池待转移时其分配详情也同步隐藏。真实 PostgreSQL 覆盖源池和分配分别待转移。
- **P2，统计权限**：无 `pools:get` 的管理/投放/活动角色可看元数据，但直接详情曾返回真实客户数。详情与目录统一清零统计，覆盖四类 metadata-only 角色。
- **P2，目录与详情不一致**：只有 `pools:allocation_platform_manage` 的账号能看到目录却被详情拒绝。组织空间按实际分配放行元数据，个人空间从同一 active 平台目录查找返回，不允许猜 ID 读取归档或待转移对象；不授予联系人读取或导出，统计仍需 `pools:get`。
- **P3，死代码**：删除组织分支早退后不可达的投放授权 SQL，更新注释。

补充 disabled 分配仍可读和个人平台排除记录概览保留的回归。曾怀疑 detached 旧分配影响当前来源退订数，复核 `(pool_id, organization_id)` 唯一约束和恢复流程后无法正常复现，已撤回，不计作缺陷。测试的精简数据库夹具同步增加生产已有的 transfer 字段及正确分配类型，删除重复建列。
