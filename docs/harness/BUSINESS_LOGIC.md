# 业务逻辑

## 核心对象

- **工作区**：个人工作区或组织工作区；请求必须先解析并验证当前用户的成员资格和组织状态。
- **客户列表与客户**：客户列表承载客户集合；客户列表和客户默认归属创建者，组织经理可以在当前组织检查成员资源，但不能代替所有者修改或发送。v6.28.0 专用管理员导出允许本组织数据导出，保持打码边界，普通成员不可导出。
- **模板与活动**：模板和活动支持 `private`、`organization`、`global` 可见性；可见不等于可使用、修改或发送。
- **用户与角色**：系统用户角色、客户列表角色、组织成员/经理角色和个人 API Key 是独立边界，权限只能收窄，不能扩大资源所有权。
- **一级公海与二级列表**：一级公海保存全局联系人主数据；二级列表只保存一级联系人到组织的分配关系，不复制邮箱。每个“一级公海 × 组织”只允许一个已绑定二级列表，二级列表的手动移除、回复退订和投诉均产生组织维度的逻辑剔除状态，并在一级公海中可见该组织的剔除标记。
- **公海回件邮箱**：回件邮箱配置在二级列表上，由组织工作区管理员维护。一级公海没有可供组织继承的明文回件邮箱；组织选择一级公海投放时，最终回件邮箱必须由目标组织的二级分配解析。

## 请求与发送流程

- **导出当前名单**：`internal/dataexport/query.go` 只读取目标工作区；公海分配名单导出实际移除原因，转入私有由操作者手动标记，不按私有列表匹配推断。恢复后不展示旧移除原因。不提供独立公海转私域导出，不伪造转入时间、操作人或不存在的退订统计。
- **导出任务权限**：`internal/dataexport/service.go` 在生成、下载时重查管理员身份；账号禁用、组织归档、成员资格丢失即拒绝。打码/追踪配置变化使旧文件失效。文件七天过期清除，任务保留行数、范围和下载审计。

1. `internal/auth` 验证 session、Basic/token 或 Bearer API Key，并绑定身份与 Key scope。
2. `cmd/organizations.go` 解析选定工作区；服务端重新验证组织活动状态和成员资格。
3. `cmd/workspace_permissions.go` 与 `internal/core/workspace.go` 分别应用传统功能权限和资源 `read`/`use`/`copy`/`manage` 检查。
4. 写入在事务中锁定并重新验证组织、所有权和转移状态，避免检查后状态变化造成越权。
5. 活动通过 manager 生成消息，经 messenger 投递；跟踪、退订、归档和退信由对应后台模块处理。

## 公海投放与回件邮箱不变量

- 最高管理员向组织划分一级公海时，在公海管理窗口选择“目标组织”。该选择只决定二级列表和联系人分配的组织归属，不切换当前工作区、不要求管理员加入组织，也不产生 `organization_members` 记录；回件邮箱由组织管理员在自己的工作区配置，普通组织用户只能操作当前组织的二级列表。
- 组织在二级列表手动移除联系人时，只写入 `(一级公海, 组织, 公海联系人)` 的剔除记录，不删除一级公海联系人，也不影响其他组织。该组织后续选择一级公海投放时，收件人解析必须过滤这条记录。
- 一级公海活动和二级列表活动在生成投递快照时都必须保存一级公海联系人内部 ID、目标组织、实际来源二级列表和最终回件邮箱；同一活动内按联系人内部 ID 去重。
- 活动选择二级列表时，最终回件邮箱取该二级列表的统一配置；活动选择一级公海时，最终回件邮箱取该联系人在目标组织有效二级分配的回件邮箱。活动配置页、预览、发送快照和回信审计均需显示“一级公海受众 -> 二级列表 -> 回件邮箱（组织）”的解析来源。
- 客户真实邮箱只在服务端投递及回信处理链路可用；普通组织用户不得获得可复制的客户真实地址。二级列表回件邮箱是公司内部地址，组织用户和最高管理员可在活动配置、预览、发送快照及回信审计中直接查看，但最高管理员不在公海拆分弹窗代为配置，不得将其当作客户联系方式导出。
- 回复、明确退订和投诉只能剔除实际投递来源所属组织的二级分配；不能通过重新选择一级公海绕过剔除，也不能影响其他组织。
- 剔除记录必须可审计并可恢复/重新分配，但恢复动作只能由拥有相应二级列表管理权的组织管理员或最高管理员执行，且恢复不能自动恢复历史活动收件人快照。
- 数据库约束每个“一级公海 × 组织”只有一个已绑定二级列表，从而使该组织内的联系人归属和一级公海活动的回件邮箱唯一可解析；若未来允许多个归属，必须移除此约束并要求活动显式选择二级列表，不能静默猜测回件邮箱。
- 一级公海活动在草稿阶段可保存，但目标组织没有有效二级归属或回件邮箱时，预览和发送必须阻断，不得回退一级或系统默认邮箱。

## AI 入站回信不变量

- 只有全局 AI 设置和回信邮箱的逐邮箱开关均启用时，后台 worker 才能将该邮箱的回信正文送往 OpenAI 兼容接口；正文是非信任数据，模型只能返回固定意图，不能下达任意动作。
- Worker 必须从回信邮箱的 `organization_id`、`user_id` 约束客户匹配；地址不存在、在该边界内不唯一、成员已离组、组织已归档、自动回复、低置信度或非明确意图时，只记录审计结果而不改变客户。
- 只有明确 `unsubscribe` 和明确 `complaint` 可自动执行；二者都将该工作区内的匹配客户设为 `blocklisted` 并将其全部客户列表成员关系设为 `unsubscribed`。投诉额外创建 `source=reply_ai` 的退信记录，不能伪装为邮件服务商反馈。
- 对公海投放产生的回复，处理器必须使用投递快照中的一级公海联系人、目标组织、来源二级列表和回件邮箱定位分配关系；自动处理只更新该组织二级列表的剔除状态，不得把一级公海联系人全局拉黑或从其他组织移除。
- 每封回信以邮箱与稳定消息键去重；租约、失败重试和投诉事件唯一键保证崩溃恢复不会重复拉黑或重复写入投诉。终态审计记录不保留用于模型调用的正文。

任何新业务流程都必须说明：所属工作区、资源所有者、可见性、可执行动作、事务边界和失败回滚行为，并补充相应测试。

## 退信邮箱只读检测（2026-09-08）

- 来源：用户确认的“读取最新一封、解析发件人/主题/退信地址、只读检测”需求。
- 检测只读取当前 POP 会话最高序号邮件，不扫描寻找退信，不保存表单、不发送邮件、不调用 DELE、不生成退信事件、不执行客户退订/拉黑。后台既有轮询不受此保证约束，仍可能独立处理邮箱；邮箱被占用时报错供重试。
- 普通邮件属于读取成功但未识别退信，空邮箱单独提示；不会把通知发件人或普通 To 字段当成失败收件人。
- DSN 各收件人块优先 Final-Recipient，再 Original-Recipient，再 X-Failed-Recipients；正文推断明确标记 body_inferred。摘要取外层邮件，日期优先 Received，缺失则以 Date 标记回退，未知不补当前时间。
- `starttls` 与 `tls_enabled` 互斥；旧配置缺失 `starttls` 时视为 false，不需要迁移。检测和保存后的后台收信使用同一连接模式。
