# 营销概览与失败客户补发后端方案（2026-10-21）

## 目标与口径

- 概览的「计划发送、已发送、未发送」来自活动收件人快照；「失败客户」是存在发送失败事件、且当前仍未发送的去重收件人，不等于累计失败尝试 `send_errors`。
- 失败客户名单按收件人去重，展示最近一次失败原因、次数及当前收件人状态；历史失败后已成功发送者从当前失败名单退出，但仍保留在既有 `/send-errors` 历史报告。
- 私域与公海共用接口形状，公海额外给出组织维度进度。身份、邮箱、诊断与导出继续遵守既有活动/客户/公海权限及脱敏规则。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/campaigns/:id/delivery-overview` | 总量、进度、失败客户数、公海各组织进度 |
| `GET /api/campaigns/:id/failed-recipients` | 分页、搜索、原因筛选的去重名单；返回补发资格 |
| `GET /api/campaigns/:id/failed-recipients/export` | 相同筛选条件的 Excel 全量导出 |
| `POST /api/campaigns/:id/failed-recipients/retry` | `{recipients:[{type:"private"|"pool",id:number}]}`，仅接受已暂停且当前未发送、有历史失败的指定收件人 |

## 补发不变量

1. 仅能对已暂停活动选择当前未发送的失败收件人；完成、运行、排期或延期状态不直接启动，避免与现有发送管道并发。
2. 一次最多选择 500 人，去重并全部校验；任何无效 ID、已成功发送、迁移/退订/拉黑或失去投放资格者均使请求失败，不部分启动。
3. 在同一个工作区/活动锁事务内写入选中标记与活动运行状态。调度器只领取选中收件人；正常的额度限制、SMTP、回复路由、渲染和失败计数逻辑继续生效。
4. 本次选中补发耗尽后，若活动仍有未发送收件人则回到暂停，否则完成；清理选中标记。手动普通继续发送时清理补发模式。
5. 操作写审计，只记录活动和选中人数，不记录客户邮箱或错误原文。重复请求在活动已运行时返回冲突，不会重复入队。

## 验收

- 私域与公海分别覆盖多次失败去重、成功后退出失败名单、分页/筛选/导出和敏感字段权限。
- 选中 2 人时只有这 2 人被领取；发送成功更新原快照，其他待发送客户保持原状态。
- 过期选择、并发启动、跨工作区、无权限、发送中、额度延期及暂停恢复均安全。
- 迁移可用于现有数据库；Go 测试、文档检查和本地 Docker 后端同步通过。
