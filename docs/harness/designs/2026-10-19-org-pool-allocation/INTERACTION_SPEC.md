## 2. 设计前的源码核对与差距（历史基线）

| 当前源码 | 已确认行为 | 设计要求 |
| --- | --- | --- |

## 3. 三类对象与不可变边界

| 对象 | 可以改变什么 | 绝不能隐含改变什么 |
| --- | --- | --- |
| 一级公海主数据 | 联系人字段、主数据导入、联系人新增/归档/永久删除 | 不由“管理组织分配”获得这些能力 |
| 组织公海分配 | 来源公海与组织之间的绑定、成员关系、名称和分配生命周期 | 不改联系人姓名、邮箱、部门、黑名单，也不复制主数据 |
| 组织投放授权 | 某个 `pool_id × organization_id` 是否允许投放 | 不授予成员浏览、分配维护、主数据编辑、导出或发送权限 |

关键标识分开：一级 `pool` 的列表 ID、分配 `org_pool_allocations.id`、分配列表 `list_id`、组织 ID、联系人 ID。API 不得混用分配 ID 和分配列表 ID。请求中的名称、组织标签、列表类型和前端 capability 均不能作为授权证据。

来源公海和目标组织在既有分配上只读。换组织或换来源必须选择另一个分配目标，不能通过改字段“搬家”。分配不配置回信邮箱，仍由组织邮箱管理流程处理。

## 4. 权限模型

### 4.1 范围与动作分开

1. 最高平台管理员沿用服务端 `IsPlatformAdmin()`，可跨组织管理；不需要加入目标组织，也不切换当前工作区。
2. 普通 `pools:manage` 只允许维护当前可写组织的分配，组织经理身份本身不授予动作权限。
3. 若需委派“只管理分配”的平台操作员，新增一项业务级能力“跨组织管理公海分配”，已实现稳定 ID `pools:allocation_platform_manage`；不按按钮继续拆分。它允许跨组织分配维护，但不获得主数据、投放授权或联系人浏览。
4. 新能力不由 `organizations:platform_manage`、`pools:master_manage` 或 `pools:delivery_manage` 推导，不通过升级给现有角色自动授予。没有新授权的旧角色保留原功能门，但不再借投放授权管理跨组织操作分配；此兼容性变化需明确写入升级说明。
5. 权限组合取并集后仍受目标组织状态、来源状态、分配状态与 API Key scope 限制。后端 HTTP 与 Core 事务都检查，不依赖按钮显隐。

### 4.2 动作矩阵

| 业务动作 | 普通组织分配管理者 | 委派跨组织分配管理者 | 仅主数据维护者 | 仅投放授权管理者 |
| --- | --- | --- | --- | --- |
| 分配元数据与管理入口 | 当前可写组织 | 所有允许管理的组织 | 不因此获得分配能力 | 仅授权所需的最小目标摘要 |
| 改名、备注、分配启停 | 本组织，需 `pools:manage` | 跨组织，需新业务能力 | 否 | 否 |
| 分配、移除、恢复成员 | 本组织，需分配管理能力 | 目标组织，需新业务能力 | 否 | 否 |
| 在 UI 浏览成员/候选客户 | 另需 `pools:get`，按可读数据范围 | 另需 `pools:get`，限明确目标分配和被允许的候选范围 | 仍按查看权限与既有主数据范围 | 否 |
| 创建绑定 | 本组织且已有投放授权 | 可预建未授权的分配，不自动授权 | 否 | 否 |
| 解除/恢复绑定 | 不提供平台级解除入口 | 可以，受引用与状态校验 | 否 | 否 |
| 授予/撤销投放授权 | 另需 `pools:delivery_manage` | 另需 `pools:delivery_manage` | 否 | 可以 |
| 编辑/导入/删除主数据 | 另按主数据或联系人编辑权限 | 新能力不扩大主数据范围 | 按原主数据权限 | 否 |
| 导出、敏感信息、发送活动 | 均另查各自权限与数据范围 | 均另查各自权限与数据范围 | 不隐含授予 | 不隐含授予 |
| 操作记录 | 另需 `audit:get`，本组织范围 | 另需 `audit:get`，仅目标分配的相关记录 | 不隐含授予 | 不隐含授予 |

最高管理员沿用已有功能权限豁免和敏感信息规则；这不允许创建分配时自动授权，或把移除变成永久删除。归档、转移、来源无效等业务限制仍需执行。

委派跨组织管理者的联系人响应继续脱敏，不能通过分配编辑获得真实邮箱、属性全集、其他组织私域或全平台审计日志。`customers:sensitive_read` 不在此设计中被扩大为跨组织公海明文权限。

没有 `pools:get` 时允许看分配名称、来源、组织、状态等最小管理元数据；不请求成员行、客户搜索结果或客户数量。UI 不提供无法选取对象的成员管理按钮。已有 API Key 如允许按 ID 修改关系，仍须同时通过分配动作、明确范围、对象归属和 scope 校验。

## 5. 列表入口与导航

### 5.1 子行

- 保留现有父子层级、组织/类型筛选、匹配数量与按完整分组分页。
- 子行显示“查看客户”（有查看权限时）、“管理分配”（有分配管理权限时）、“更多”（至少有一个可执行低频动作时）。
- “更多”可包含编辑分配信息、操作记录和解除分配；不能出现普通列表的发起营销、导入主数据、永久删除客户。
- 子行不接入普通列表批量删除，不因为增加分配管理而变为可批量删除行。
- “查看客户”继续进入既有分配客户路由；“管理分配”进入专用管理容器。不要把 `canManageList()` 对分配直接改成 true。
- 保留来源公海不可见时的受限上下文规则，不能为了展示面包屑额外拉取未授权的父资源。

### 5.2 URL 与返回

建议用显式查询状态表达管理目标，例如 `?allocation_id=123&manage_tab=members`；该 ID 是分配 ID，不是分配列表 ID。独立页备选则使用专用路由承载相同状态。

刷新后恢复已授权目标和页签；直接输入 ID 仍走服务端校验。关闭时只移除管理参数，保留原列表筛选、页码和展开状态，并将焦点还给触发入口。管理容器和背景列表分别滚动。

### 5.3 跨组织选择

从子行进入固定当前来源与目标组织；从父行管理入口进入可选择目标组织。支持搜索组织，显示“已绑定/未绑定/已解除”。普通管理者仅当前组织，不发起全组织目录请求。

切换组织不切换工作区、不添加成员身份、不修改任何授权。请求返回前校验目标令牌，旧组织的迟到响应不得覆盖新组织。切换会清空成员选择与成员页码；每个组织的名称/备注草稿独立保留。脏表单切换要确认“放弃修改/继续编辑”，提交中禁止切换目标。

## 6. 页面区块与状态

### 6.1 固定上下文

始终展示分配名称、只读来源公海、只读目标组织，并提示“跨组织管理，不切换工作区”。区分“分配状态”和“投放授权”，不使用单个“已启用”表达两者。

管理内容由“客户分配”“分配信息”“操作记录”组成。无成员查看权限时默认进入分配信息，客户页签显示无查看权限说明，不向 API 请求成员数据；无审计权限时不显示操作记录入口。

### 6.2 三组独立状态

| 维度 | 拟议状态 | 含义 |
| --- | --- | --- |
| 分配生命周期 | 已启用 / 已停用 / 已解除 | 控制该组织分配是否可作为有效受众来源 |
| 投放授权 | 已授权 / 未授权 | 是否允许该组织使用来源公海投放 |
| 成员关系 | 正常客户 / 已移除客户 | 是否在该组织分配中有效 |

联系人另有 active、archived、blocklisted 主数据状态，不能和成员关系混为一谈。“正常客户”表示未移除，不保证联系人可以发送；黑名单和归档状态须有独立提示。

生效受众需要同时满足：组织与来源可用、分配启用、投放已授权、成员未移除/未剔除、联系人可投递，以及既有发送权限与回信路由规则。全组织公海投放同样受分配停用和组织剔除约束，不能绕过。

生命周期建议在分配记录上新增独立状态与变更时间/操作者，不把普通列表归档字段当作授权开关；迁移默认既有绑定为已启用。具体迁移需在实现阶段验证现有归档数据与历史引用。

## 7. 完整操作流程

### 7.1 创建与绑定

1. 在来源公海中选中一个组织；加载目标状态成功后才显示创建表单。加载失败只显示错误和重试，不能误判为未绑定。
2. 未绑定显示名称（按组织预填，去空白后 1–200 字符）、可选备注、来源和组织只读信息。
3. 普通组织管理者无投放授权时创建按钮不可用，说明需联系授权管理者；有授权时可创建。
4. 平台管理员/独立跨组织分配管理者可以预建“分配已启用、投放未授权”的绑定；显示“创建不会开通投放授权，当前不能用于组织投放”。
5. 点击“创建分配”只调用创建接口。即使操作者同时有投放权限，也不写授权表、不自动串接授权请求。
6. 事务内复核组织启用、来源有效、管理范围和 `pool_id × organization_id` 唯一性；按照既有部门规则回填来源内匹配该组织的成员，不创建联系人、不解除原有黑名单。
7. 已有逻辑解除记录时显示“恢复绑定”，不得另建重复记录或自动抹掉原成员移除记录。
8. 成功后刷新目标摘要、树子行和受影响计数，保留列表筛选与其他组织草稿。并发重复创建返回冲突并提供重新加载，不清除用户输入。

### 7.2 编辑分配信息

仅可修改名称、可选备注；来源公海、组织、创建人、可见性、列表类型和回信邮箱均不在可编辑白名单。备注建议限制 1000 字符，纯文本展示。

有改动才启用“保存修改”。成功更新标题与树行，不重置当前客户筛选；校验失败保留草稿并聚焦对应字段。使用版本号或更新时间做乐观锁，冲突时提示“分配已被其他人修改，请重新加载后再保存”。

### 7.3 分配已有客户

打开选择器，只列出该来源公海中操作者被允许读取和分配的候选客户；不返回其他公海或其他组织私域数据。最高管理员可从来源公海选取；普通/委派操作员不能仅凭关系管理权限枚举整个来源池。候选范围策略须由服务端明确计算，未获候选读取范围时禁用选择器并说明原因。

已分配客户标记“已在分配中”，不可重复添加；已移除客户提供明确的“恢复分配”流程，不通过添加悄悄清除组织剔除。筛选和翻页后清空选择，不默认跨页全选。

确认显示来源、目标组织和客户数。服务器检查每个联系人确属来源池、目标分配启用且范围有效；有限批次关系修改采用全成功或全回滚，避免前端伪装成全部成功。幂等重试不得重复增加计数。这里没有客户主数据新增、文件导入或黑名单解除。

### 7.4 从分配移除

“正常客户”每行提供“从分配移除”，当前页多选后提供“移除分配”。确认弹窗标题为“从测试组织的分配中移除 N 位客户？”，要求填写移除原因；客户端和服务端对原因执行相同非空、长度约束。

确认文案：“只移除该组织的分配关系；公海主数据与其他组织分配保留。该组织通过一级公海投放也会排除这些客户。”

默认焦点在取消。提交中禁用重复操作，锁定目标。成功后清空已处理选择、刷新正常/已移除计数和父子行计数；当前页空时回退到最后有效页。移除原因写入本组织关系/剔除记录，不写客户共享属性。

### 7.5 恢复分配

在“已移除客户”筛选下显示“恢复分配”，正常列表不显示。确认目标组织、客户数和“恢复不解除公海联系人黑名单，也不开通投放授权”。

恢复只撤销目标分配/组织的对应移除和剔除状态；不影响其他组织，不改历史已发送快照或已转入私域的客户。黑名单/归档联系人可以保留关系恢复结果，但仍明确标记不可投递；不得将恢复文案表述为恢复发送。

### 7.6 停用与重新启用

“分配信息”中提供生命周期操作，和投放授权区块隔离。停用确认显示组织、来源及经服务端预检得到的受影响未完成活动；预检失败或缺少活动信息读取范围时不能显示虚构的零影响。

停用保存绑定、成员关系、移除记录和投放授权，但阻止该分配继续参与受众解析与后续可拦截投递。所有发送路径（普通组织、跨组织、排队、延后、重试、恢复）在实际投递领取边界重验状态。已经交给 SMTP 的在途邮件可能无法撤回，确认文案必须说明，不能承诺“绝无后续邮件”。

重新启用只恢复分配生命周期，不恢复被撤销的授权、已移除成员或联系人黑名单。未授权时成功后提示“分配已启用，投放仍未授权”。归档组织、无效来源或待转移资源不能通过最高管理员豁免恢复写入。

### 7.7 投放授权独立操作

在独立摘要区只读展示授权状态。有 `pools:delivery_manage` 才显示“管理投放授权”，进入单独操作流程；无权限不得渲染可点击开关。

授予/撤销都明确展示来源公海与目标组织、影响范围并二次确认，独立请求、独立反馈、独立审计。授权失败不回滚已成功的分配信息保存，也不能显示整个操作成功。撤权保留分配与成员；再次授权不自动恢复已停用/已解除分配或已移除成员。

投放授权只影响组织用池资格，不替代活动发送权限、跨组织发送权限、邮箱权限或回信路由条件。分配未绑定/已停用时即使授权成功，仍提示无法投放的具体原因。

### 7.8 解除与恢复绑定

“更多”中的危险动作叫“解除分配绑定”，不叫“删除列表”或“删除客户”。只对最高管理员/明确跨组织分配管理者开放。采用逻辑解除，保留分配 ID、历史成员、剔除记录、活动与收件人引用；不能调用通用列表删除。

先执行服务端引用预检。存在运行中、排队、暂停待恢复等未完成活动引用时，阻止解除并提示先处理活动；没有活动查看权限时只给安全的阻断原因，不泄露名称和收件人。已有完成历史不妨碍逻辑解除，但必须保留快照。

通过预检后要求输入目标组织名称并填写原因，确认“不会删除客户，也不会撤销投放授权；该分配不再参与投放”。最终事务再验引用，避免预检与提交之间出现新活动的竞态。

解除后子行保留在“已解除”管理状态中；组织目录显示“已解除”，不得显示成无历史的“未绑定”。恢复绑定复用原 ID，默认进入已停用，要求显式重新启用；保持原成员移除与剔除状态，不自动重新回填，不更改授权。

### 7.9 操作记录

有 `audit:get` 且具备目标范围才请求记录。只查询当前分配、来源与目标组织相关的创建、改名、成员调整、停用/启用、解除/恢复和关联授权事件；按时间倒序、服务端分页。

记录操作者、动作、目标组织、来源公海、分配 ID、数量、原因、前后状态和结果。新生命周期动作优先复用 `RecordTx` 保证业务与审计同事务；不把密码、完整邮箱集、邮件正文或附件写入 metadata。既有审计中间件不能重复记同一成功业务事件。

跨组织查看该分配审计不授予全平台日志访问。失败/拒绝事件继续使用独立安全审计流程，不伪装成事务成功事件。

## 8. 异常、并发与可访问性

| 情况 | 必须表现 |
| --- | --- |
| 初始化加载中 | 骨架/加载说明，不能显示可提交创建表单 |
| 加载失败 | 区块内持久错误与重试，保留目标，不退化为“未绑定” |
| 没有成员 | 说明当前目标/筛选没有数据；有能力才提供分配已有客户入口 |
| 401/权限被撤销 | 停止写入，清除越权数据显示，提示重新登录或无权限 |
| 403 | 明确缺少对应动作/范围，不建议无权限用户切换空间绕过 |
| 404 | 安全提示对象不存在或不可见，不用不同文案探测其他组织 |
| 409 | 展示状态/版本/引用冲突，保留草稿，重新加载后再确认 |
| 校验错误 | 字段旁显示原因，移除/解除原因不丢失 |
| 网络超时 | 提示结果待确认，先重新读取目标状态；不盲目重复执行高风险写入 |
| 批量提交失败 | 有限批次全回滚，保留选择；禁止静默逐条成功/失败混合 |
| 计数刷新失败 | 明示数据可能过期并提供重试，不能回滚已确认的业务成功 |
| 切换组织时迟到响应 | 丢弃旧目标结果，不覆盖新目标状态、草稿或 loading |

组织、来源、分配行的锁序在所有写入和发送引用创建路径保持一致；写前在事务内复核目标状态。前端乐观能力摘要只负责显隐，不替代服务端判定。暂停/解除与新建活动并发必须保证一致结果。

只有一个成员状态下拉，不能既用下拉又用重复“查看已移除客户”入口；第一张 AI 图中的重复入口在实现时去掉。图中蒙层/抽屉宽度与背景表格压缩只是示意，真正实现不得压碎名称列。

沿用 `UI_DESIGN_SYSTEM.md`：蓝色主色、现有字体、中性表面、6px 圆角、轻分隔、无装饰渐变。1440px/1644px 桌面检查布局；390px 手机上抽屉/弹窗全屏、组织列表改为可搜索选择器、成员行按移动卡片展示，不产生页面横向溢出。

关闭/切换脏表单必须确认；Esc 和遮罩点击不得悄悄丢草稿。危险确认默认焦点在取消，焦点陷阱完整，关闭回到触发入口。图标有 tooltip 与 aria-label，错误与字段关联，加载区 aria-live，状态不能只靠颜色表达。分页复用 `AppPagination`，更换每页条数回第一页但保留筛选。

## 9. API 与实现约束（已落地，具体路由见第 12 节）

优先扩展专用分配 API，禁止借 `PUT/DELETE /api/customer-lists/:id` 放开分配类型。具体路由已与注册表和 API 文档统一。动作成功返回布尔结果，随后通过详情 GET 读取新状态与版本。

| 拟议接口/能力 | 要求 |
| --- | --- |
| 分配详情与 capability 摘要 | 分开返回安全元数据、生命周期、授权状态和动作能力；不隐含联系人 DTO |
| 分配专用更新 | 只接收 name/description/expected_version，拒绝组织/来源/类型/可见性/回信邮箱变更 |
| 分配 lifecycle 操作 | 独立 action、reason、expected_version；返回新版本与状态，不写授权表 |
| 引用预检 | 按分配范围核验活动；提交时再次检查，预检结果不作授权凭证 |
| 组织目录/目标摘要 | 按调用目的分开校验分配管理范围与授权管理范围，只返回最小字段 |
| 成员查询/候选查询 | 另查查看权限、目标范围与字段脱敏；分页搜索不泄露越权总数 |
| 成员分配/移除/恢复 | 复用既有关系语义，事务中检查来源成员关系、组织状态、分配生命周期与排除记录 |
| `POST /api/pools/allocations` | 创建不写 `pool_organization_permissions`，平台预建可返回未授权摘要 |
| 投放授权 API | 保留独立权限与请求，不能通过 lifecycle/name/member 负载触发 |
| 分配操作记录 | 当前分配的受限查询，不复用无边界全平台日志读取 |

服务端构造明确 actor/access 上下文，拆分 `canManageAllocationsAcrossOrganizations`、`canManageDelivery`、`canManagePoolMaster`，避免一个 `platformAdmin` 参数同时控制三者。兼容路径、别名 API、Core 直接调用和 Key scope 都要核查，不能只修 UI 正常路径。
