# 第二批存量界面视觉评审

范围：按 `UI_DESIGN_SYSTEM.md` 的现状规范评审所给桌面 1440×900、手机 390×844 截图；只据静态画面判断，不打分。

- [问题 1] 维护与待转移确认弹窗：正文直接开始、没有标题 → 弹窗有可辨认的危险操作标题，数量、对象和取消/确认仍清楚。
- [问题 2] 待转移资源桌面第 1 页：20 行清单把接收成员与转移按钮推到首屏之外 → 首屏可辨认下一步及其作用范围，保留可扫描的名称、原所有者和时间。
- [问题 3] 编辑器手机设置态：属性面板占据几乎全部编辑区，画布只剩窄条且底部保存未出现在视口 → 当前画布/设置模式及返回路径清楚，主操作可到达，内容不被横向裁切。

## 观察与修正目标

1. `03-maintenance-confirm.png`、`20-pending-real-confirm.png`：两处弹窗均无标题，仅靠正文解释“清理未确认订阅”和“转交资源”。这偏离现状规范的模态框标题要求；危险动作的识别依赖读完整段文字。给弹窗明确标题并保留正文中的范围、实时重算与不可恢复提示；在 1440×900 下检查标题、取消焦点和确认按钮的层级。截图可见取消按钮焦点，但键盘行为未验证。
2. `18-pending-real-page1.png`：27 项真实资源按原表格分页，名称、类型、原所有者和时间可扫描，分类计数也与总数对应。但第一屏的表格持续到视口底部，接收成员与“转移资源”在整页截图末端；用户扫描后需滚至底部才看到下一步。调整同一工作区内的空间分配，使首屏能找到接收成员与主动作，同时不牺牲清单的名称和数量。`19-pending-real-page2.png` 的 7 项较短清单没有这一问题。不要以缩小表格字号或隐藏字段换取空间。
3. `09-editor-mobile-settings.png`、`10-editor-mobile-canvas.png`：工具栏保持在面板上方，中文属性与画布切换已经可见。设置态的画布仅露出约一列窄边，手机首屏也未见保存/取消；画布态可以看到内容块，但主操作同样在截图视口外。让面板切换的当前状态与返回画布入口更明确，并核对 390×844 实际滚动时底部主操作能到达、不会被固定层遮住。静态整页图不能证明按钮不可达，因此此项是可见性与待操作核验问题，不判定流程阻断。

可直接删减的文案：维护页首的“数量为查询时的结果……”与每个预览下的“创建时间早于……”承担不同含义，暂不删；待转移页底的范围及回邮合并说明涉及操作后果，也应保留。未发现可无损直接删除的填缝文案。`Sample visual template` 是现有邮件名称，JSON/HTML 和模板变量属于原文或技术名，不据截图要求翻译。编辑器画布里的破图与“图片”占位来自临时 QA 邮件内容，不作为界面视觉缺陷。

保留：维护页的选择条件 → 数量/单位/日期 → 危险操作顺序及零条禁用；待转移的 27 项分类数量、原表格/移动卡片和含组织、接收人的确认内容；编辑器原有 MUI 骨架、蓝色品牌操作及中文属性选项。未观察到偏离现有品牌色、圆角或组件风格的证据。动效、可访问名称、真实提交与失败状态不能由这组静态截图确认。
