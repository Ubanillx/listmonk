# 发件服务（BestEDM / U-mail）

平台管理员或获授“查看发件服务”（`delivery_provider:get`）的用户可从左侧“发件服务”进入，地址为 `/admin/delivery-provider`。在“用户 → 用户角色”的“发件服务”业务组中勾选此权限；普通角色默认不授予。无权限时不显示菜单，直接打开页面会进入无权访问页，接口返回 403。

此权限允许查看平台账号资料、发送报表、失败邮箱、投递日志及导出 Excel，数据不随当前组织工作区变化，授权前应确认可查看全平台邮箱地址与日志。普通系统设置、邮箱配置或组织管理员身份不隐含此权限；个人 API Key 仍不能访问。账号配置和连接测试仍仅限平台管理员，委派查看者的账号页只显示资料，不显示凭据表单。

## 连接账号

以下操作仅限平台管理员；委派查看者在未配置时会看到联系管理员的提示。

1. 打开“账号设置”，填写 BestEDM 网页登录账号及密码。
2. 点击“保存并连接”。系统先保存，再使用已保存凭据查询服务商账号与服务信息；验证失败会保留结果，刷新页面后仍可查看。
3. 保存后可点击“测试已保存账号”，无需再次填写密码。密码留空保留已有值；换账号必须同时填写新密码。

保存操作使用版本校验。另一个管理员更新过配置时，当前保存会被拒绝；刷新配置后再重试。一般系统设置接口不能修改这组凭据，读取设置不会返回密码。

连接凭据存于数据库 `settings` 的 `integration.bestedm` 专用记录，采用与现有 SMTP 设置相同的数据库机密保护方式；不写入前端本地存储，也不回传已保存密码。数据库及其备份应按含 SMTP 密码的机密数据管理。接口地址固定为 `https://www.bestedm.net/mm-ms/apinew/`，验证证书，不跟随重定向，真实账号始终通过后端 HTTPS Basic Auth 查询。

## 页面排版与工作流

- **总览**：日期查询条件、额度/发送量/投递成功/失败四张指标卡，下方展示按日发送量趋势、服务状态与统计明细。
- **发送分析**：统一日期与批次筛选，左侧按批次分组、右侧按邮箱汇总失败地址。批次组按最近统计日期倒序，组内记录也按日期倒序；每组有独立标题和记录数，分页按完整批次计数，不拆分同一批次。批次从所选日期的统计结果自动生成，无需输入标识；选择下拉、点击分组标题或任一记录立即联动指标与失败明细，取消选择恢复日期范围。刷新日期后重新加载批次，失效批次自动清空。错误类型与邮箱搜索可组合；Excel 导出沿用已成功查询的日期、批次、类型及当前搜索，覆盖全部匹配邮箱及错误次数。
- **投递日志**：指定日期和完整收件邮箱后按需查询，不自动轮询这个有每日调用次数限制的接口。
- **账号设置**：左侧连接配置及持久化测试结果，右侧账号资料、服务状态、额度、有效期与计量方式。

页签写入 URL，切换页签不重建页面、不丢失当前草稿。各表独立分页与滚动，快速切换批次不会显示旧请求结果。旧 `tab=failures` 链接仍打开发送分析。点击“查日志”会带上邮箱与当前批次，并立即查询一次：日期取左侧该批次最早的统计日期；未选批次时，取全部已加载统计中最早的日期，不受分页影响。没有有效统计日期时回退到上次成功查询的开始日期，不使用尚未查询的日期草稿。统计日期不代表已确认的实际发送日期，如查无记录可调整日期后再次查询；不会自动轮询、跨日期搜索或重试。

## 数据来源

报表只有服务商真实数据，没有演示或样例模式，`mode=demo` 等参数会被接口拒绝。查询失败直接显示错误，不会回退成示例数据或零指标。

指标卡按额度（浅紫）、发送量（浅蓝）、投递成功（浅绿）、投递失败（浅橙）着色，明细数字沿用对应颜色。

## 排版与阅读

页面按“页头 → 页签 → 筛选条 → 指标 → 明细”依次收拢，同一区块内元素间距统一，表格单元格留出更多水平空间，数字列右对齐并使用等宽数字，便于纵向比对。页头不重复展示平台范围说明，范围条与日志提示不带装饰竖线。发送分析桌面左右两栏等高、分页底部对齐，统计口径说明置于两栏下方；宽表只在自身容器内横向滚动。

窄屏（≤1215px）发送分析改为上下排列；手机（≤768px）指标两列、筛选与工具栏纵向排列，页签分为两行。
## 数据解释与限制

本功能读取账号信息、服务信息、发送统计、失败地址、详细日志五个接口。邮件发送继续使用已有 SMTP 配置；API 查询成功不能证明 SMTP 认证或投递成功。

服务商数据不自动写入 Listmonk 活动的已发送数、退信或客户状态，既有活动统计不与其混合。服务商批次和活动之间还没有经过验证的映射。

SMTP 无效地址按批次获取不准确。按日期查询的地址不能据此归属到某个活动。错误类型 1、2、3 按文档要求须指定批次或统计任务 ID；页面允许选择这些类型，但未选批次时会提示先选批次，选中后自动按该类型查询。查询全部类型或无效地址可按日期进行。失败导出缺少单端日期时，本系统显式把另一端补为同一天。

失败地址按邮箱去除首尾空白、忽略大小写合并，一行对应一个邮箱，保留各类错误、不同说明及各自次数。错误次数是当前查询范围内服务商返回记录的出现次数，不代表 SMTP 真实尝试次数；筛选类型或批次后重新计数，不跨查询累计。页面、分页数量和 Excel 均使用同一汇总口径。原始 API 不带 `group_by=email` 时仍返回逐条记录，兼容已有调用方。

## 失败地址的客户关联与黑名单

失败地址每行会在当前工作区内按邮箱匹配私域客户与公海联系人，并在操作列提供两个纯图标按钮：查日志（text-box-search-outline）与加入/移出黑名单（account-cancel-outline / lock-open-outline），悬停显示文字说明，aria-label 同步。未匹配任何客户的地址只保留查日志，黑名单按钮置灰并提示“该地址未匹配到私域客户或公海联系人”；未匹配地址只跳过，不会创建客户、导入列表或写入任何黑名单记录。 表格支持逐行勾选与表头全选（按当前筛选，而非仅当前页）；选中后上方出现批量条，提供“批量加入黑名单 / 批量移出黑名单 / 清除选择”。

点击黑名单按钮（或批量条按钮）进入二级确认：先选择作用范围“两者 / 私域 / 公海”（数量为 0 的范围禁用），再查看按该范围过滤后的目标或地址清单，并标注“将处理 / 已列入黑名单跳过 / 无权限跳过 / 未列入跳过”。单行显示命中客户明细，批量显示每个地址将处理的数量，底部按钮只统计当前范围内实际会变更的目标。确认后服务端再次按邮箱解析目标并复核权限：私域要求 customers:blocklist 且目标在当前工作区可维护，公海要求 pools:master_manage；缺权限或已处于目标状态的条目跳过，不整单失败。

公海黑名单是联系人级共享状态，解除入口有三处：失败地址行（全部命中均为黑名单时按钮切换为“移出黑名单”）、公海客户表格的行内图标、以及公海客户批量条中的“移出黑名单”。私域客户也可在客户编辑表单中把状态改回“正常”。

指标按返回记录汇总，不累加预计总量，不假定失败分类互斥；明细中缺失的字段显示“—”，顶部合计只累加返回了该字段的记录，不会因为个别批次缺字段而整项变成“—”。服务商日期/日志时区、统计延迟、完整错误码与日志次数上限需要联调确认。本系统单次日期范围上限为 366 天，这是本地保护上限，不是服务商承诺。

服务商用 HTTP 200 携带空结果标记表示「查无记录」：日志接口返回 `{"err_msg": "未找到相应结果…"}`，统计与失败地址返回 `<result><status>no_data</status></result>`。这两种都会显示为空列表或「无记录」，是查询成功而非失败；其它 `err_msg` 文案和非 `no_data` 状态仍按错误展示。

服务商可能在 HTTP 200 响应中返回 XML 业务错误；后端同时识别业务错误及 HTTP 认证错误。XML/JSON 格式不合法、非预期根节点、空响应、超过 4 MB 和超时均返回可见错误，不把解析失败当作“没有数据”。网络请求超时为每次 20 秒，不自动重试日志查询。
