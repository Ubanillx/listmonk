### 已确认的业务规则

- 新增独立的一级公海列表类型；现有 `public` 类型继续仅表示允许匿名订阅，不能复用为公海。
- 一级公海联系人是独立的全局主数据，保存导入的客户编码、公司名称和真实邮箱。客户编码允许重复，不能作为数据库主键、去重键或写操作的唯一定位条件。
- 一级公海和组织二级列表对所有非最高管理员只返回客户编码、公司名称、状态与脱敏邮箱；真实邮箱不得出现在列表、详情、复制控件、CSV、单客户资料导出、API Key 响应或浏览器状态中。
- 一级公海始终保留完整成员。二级列表是某一级公海成员分配给一个组织的受控子集，引用公海联系人而不复制真实邮箱或形成独立客户记录。
- 最高管理员按“一级公海列表 x 组织”单独授予投放权限。获得投放权限的组织可在活动中选择一级公海，即使没有该一级列表的查看权限；服务端仅在生成投递快照时解析真实邮箱。
- 最高管理员在一级公海管理窗口显式选择目标组织；这是分配归属，不是加入组织或切换当前工作区。二级列表候选和新建列表按该目标组织读取或写入，内部回件邮箱由组织管理员在组织工作区维护。
- 活动可选择一级公海、二级列表或两者；同一公海联系人在单次活动中必须按公海联系人内部 ID 去重。
- 非最高管理员不能导出一级或二级列表的真实邮箱。按导入客户编码搜索时可返回多个候选记录，操作人从仅含安全字段的结果中选定系统内部记录后执行维护动作。
- 二级列表只能从一级公海拆分并绑定；普通列表导入一级公海是独立的维护动作。导入的客户编码可重复；仅完整规范化记录完全一致时可视为同一条记录并幂等处理，同一客户编码但任一受比较字段不一致时保留为不同记录并写入冲突审计，绝不按客户编码自动合并、生成编码或覆盖导入值。
- 无效联系人采用“剔除”而非物理删除；最高管理员可检索和审计被剔除记录。一级公海主数据及历史投递记录必须保留。
- 剔除是组织二级分配范围内的状态：只从该组织获分配的二级列表移出，不影响一级公海主数据、其他组织的二级分配或其投放资格。客户回复、明确退订和投诉也按实际投递来源所属的组织二级分配执行同一逻辑剔除。一级公海被该组织直接选为活动受众时，服务端仍按该组织的二级分配及剔除状态解析收件人，防止用一级选择绕过剔除。
- 被剔除记录不物理删除：最高管理员可跨组织查看完整审计；组织管理员仅可查看本组织二级分配范围内的剔除安全字段（客户编码、公司名称、状态、脱敏邮箱、原因和时间），不能借此恢复真实邮箱或重新加入投放范围。
- 组织在二级列表中手动移除客户时，必须在一级公海联系人上留下该组织维度的“已剔除/未分配”标记；这不是全局移除。该组织后续即使在营销活动中选择一级公海，也不得再次发送该客户；其他组织的二级分配、投放和剔除状态不受影响。一级公海界面向最高管理员展示各组织的剔除标记，组织用户只展示本组织标记。
- 二级列表可配置一个统一回件邮箱，且由所属组织管理员维护；不同组织的二级列表分别保存各自的回件邮箱。活动选择二级列表时使用该列表邮箱；活动选择一级公海时，服务端按目标组织的有效二级分配为每个联系人解析最终回件邮箱，优先使用对应二级列表邮箱，不使用一级公海的默认邮箱。回件邮箱是公司内部地址，不属于客户联系方式，组织用户和最高管理员均可直接查看完整地址，但最高管理员不在公海拆分弹窗代配。活动配置、预览、发送快照和回信审计必须明确标注“一级公海受众 / 二级列表回件邮箱（组织）”的来源。

### 已确认的回复剔除不变量

客户回复、明确退订和投诉只能影响实际投递来源所属组织的二级分配。它们不得删除或改变一级公海主数据，不得影响其他组织；最高管理员必须能在剔除记录中查看来源活动、组织、二级列表、动作、时间和原因。一级公海直接投放只面向已分配给目标组织的成员，并同样尊重该组织的二级剔除状态。

### 已确认的发送解析细节

- 同一组织下，同一一级公海联系人禁止重叠归属；约束为 `(一级公海, 组织, 公海联系人)` 只能有一个有效二级归属。需要重叠的未来场景必须改为活动显式选择二级列表，不能静默猜测回件邮箱。
- 活动选择一级公海但目标组织没有有效二级归属或回件邮箱时，允许保存草稿并显示“无可用二级列表/回件邮箱”，但预览和发送必须阻断；不得回退一级或系统默认邮箱。
- 回件邮箱在活动配置、预览、发送快照和回信审计中显示二级列表名称、组织名称、邮箱显示名及完整内部回件地址；该地址不脱敏，但不得与客户真实邮箱字段混用或作为客户数据导出字段。
