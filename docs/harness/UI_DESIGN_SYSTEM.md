# 管理端 UI 设计规范

版本：2026-11-04
适用范围：`frontend/src` 的 Vue 2 + Buefy/Bulma 管理端

回信邮箱（2026-11-05，用户指定层级）：回信地址后放“自动检测回信”总开关；开启后展示其下的“AI 处理回信”“自动处理退信”和一份共用收件连接。关闭后收起配置但保留选择与凭据，仍能保存普通回信地址。待保存状态就近显示，测试连接要求先保存。处理选择桌面并列、手机纵排，沿用 Buefy、现有浅中性表面和空间令牌，不增加装饰动效；卡片保存/测试沿用底部主次操作。方案与验收见 `designs/2026-11-05-reply-detection/README.md`。

发件服务新增“自动拉黑”管理员页签，置于投递日志之后、账号设置之前。`ProviderAutomation.vue` 用私域/公海两条规则表达两个独立配置；沿用现有中性表面、令牌、Buefy 控件、加载与焦点反馈，不增加装饰动效。对象范围和共享影响紧邻标题，草稿不改变已保存状态；预览统计放在危险动作之前，编辑后失效，执行前确认默认焦点取消。详情为分页模态表格、局部横向滚动，失败保留输入；页签换行保证第五项手机可达。设计依据：`designs/2026-11-03-provider-automation/BRIEF.md`。

自动拉黑页面（2026-11-04）：规则纵向排列在同一表面；每条标题行放客户范围、定时开关和“手动处理”次级入口。关闭时收起表单；开启定时展开失败类型与执行安排，桌面两列、≤1100px纵排。手动处理不改变定时开关。开关旁显示待保存状态，关闭已启用规则时单独提供“保存停用”，不受草稿输入有效性限制。排除邮箱按需展开。手动模式仅提供“查找待拉黑客户”，定时模式另有“保存定时设置”；系统自动检查条件后显示人数确认。共用执行记录移到规则下方，按时间倒序并支持范围筛选，手机使用现有移动表格；操作说明置底展开。对象名称、开关上移、关闭时收起配置、减少重复文案和两套规则继续关闭为用户确认；规则纵排、统一记录及次级手动入口为Agent据此推断。本轮不更换全站页头或视觉系统。

提示气泡统一挂在页面层，层级为 1000，不能依赖提高局部 z-index 穿透表格、图表或弹窗的 overflow/contain。图表提示宽度上限 420px，按钮提示上限 320px，均保留至少 8px 视口边距、长文本换行及边缘避让。指针提示随滚动关闭；键盘提示跟随仍在视口内的焦点，Escape 可关闭。卸载后不得残留节点或监听器。入口：`components/AppTooltip.js`、`utils/{chartTooltip,canvasTooltip}.js`、`components/IconTip.vue`。

第二批操作预览约定：数量来自与实际动作同范围的只读查询，明确单位和日期；查询失败不显示为零，未完成/失败/零条时禁用执行。预览位于选择条件之后、危险按钮之前，桌面同行、手机纵向，取消保留条件。待转移清单采用原表格与移动卡片，保留原所有者和时间，长名称断行。全平台清理范围只在页首说明一次，客户级联后果单独就近说明。

自动拉黑不向用户暴露预览有效期/保存版本的前置步骤：选择条件后点“查找待拉黑客户”，自动检查，再确认人数。主动作可用、检查中加载且锁定当前范围，零匹配显示结果而非置灰死路；再次开始总是重新检查。手动条件无需保存，不显示“有未保存修改”；手动运行不改变定时规则。定时设置只点一次保存，由系统完成检查与保存。仅最终确认使用危险色并默认聚焦取消。检查失败/保存失败/执行失败原位保留输入并更新历史；历史读取失败显示独立重试，不能覆盖原始错误。切换页签或离页取消待确认操作并关闭所属确认框，返回后不复用旧检查回调；隐藏的定时草稿不能影响手动查找。不添加动画，引入的反馈沿用按钮加载态和局部结果显示。

自动拉黑明细窗：默认桌面1120px、最高800px并预留视口边距，手机按视口收缩并居中。标题栏和通栏底栏不参与正文滚动，顶部关闭与底部关闭均可见；底栏不得复用表单动作组的自动外边距。邮箱与匹配客户同列，失败类型和错误记录数分开，手机复用表格卡片；无匹配客户由处理结果说明，不保留空列。分页复用AppPagination，默认20条；切页回正文顶部，失败显示原位重试，关闭焦点回触发按钮。验收须用超过一个API页的长列表覆盖滚动、跨页、改变条数、失败恢复、桌面/手机关闭，不再仅用单条fixture判断弹窗合格。

长资源清单的接收人与转移主动作位于总数之后、清单之前，首屏可见；确认框有明确动作标题并默认聚焦取消。日期型清理边界使用部署时区的00:00，明确排除所选当天。邮件编辑器手机设置采用全宽面板，并提供文字“返回画布”；编辑器保存仍由宿主表单承担，需检查手机滚动可达。

React 可视化编辑器沿用 MUI 视觉，界面跟随平台语言；工具栏图标同时具备中文可访问名称，内容块、属性与字体选项统一中文。JSON/HTML/Markdown 等技术名和邮件原文保留；窄屏通过设置面板开关在画布与属性间切换，工具栏保持在面板上方。

这份规范把管理端的视觉和交互决策固化为可检查的规则。页面优先服务于高频运营工作：快速扫描、批量处理、明确反馈和可恢复操作。

## 设计原则

1. **信息优先**：页面标题、当前工作区、主操作和数据状态在首屏建立清晰层级。
2. **克制而一致**：使用中性画布和白色工作区表面，颜色只表达品牌、状态和风险。
3. **可预测操作**：相同动作使用相同位置、图标、文案、加载态和确认方式。
4. **渐进响应式**：桌面端保证扫描密度，窄屏端优先保证操作可达和内容不被裁切。
5. **可访问默认开启**：键盘焦点、可访问名称、对比度、错误提示和状态反馈属于完成标准。

活动发送错误报告用双项概览先展示失败尝试数和聚合记录数，保持错误原因摘要、表格内容与服务端口径一致；客户身份字段在同一单元格分组展示，语义色仅作错误分类辅助。无记录、请求失败及无导出权限必须分别给出真实状态，不可用示例统计冒充线上数据。

发件服务页与营销统计页共用视觉层级：标准 `.page-header`、标题旁的服务商标签、边框内嵌标签的日期筛选、居中指标卡和中性报表分区。指标沿用当前浅蓝/浅绿/浅橙/浅紫的弱语义底色，不重复放置装饰图标；连接状态和失败分类保留带文字的语义色。趋势复用 `Chart.vue`，按发送日期补齐最近30天的缺失日期并以空值留出间隔，禁用线段跨越空档，避免把离散批次数据误读为连续发送。表头继承全局表格规则，局部样式位于 `styles/views/_delivery-provider.scss` 并通过视图 scoped 样式加载，避免影响营销统计。移动端四个页签均可达，指标双列、分析与账号区域单列，宽表仅在各自容器内横向滚动；不改变平台账号范围与数据缺失语义。发送分析按批次设置浅色分组标题和缩进日期记录，组与记录均按统计日期倒序，分页不拆组；桌面两栏等高、分页底部对齐，范围和日志提示不加竖线，页头不重复平台范围说明。失败地址按邮箱汇总，错误次数与 Excel 使用同一后端口径。失败地址的“查日志/加入黑名单”使用 `components/IconTip.vue`：气泡固定定位、按视口上下翻转并在左右边缘夹紧，长文案换行且不撑破表格滚动容器；图标按钮只保留 `aria-label` 与悬停气泡，不在单元格内占用文字宽度。

活动列表采用 B 分组列：营销活动、发送情况、客户互动、发送错误、退订相关人数。发送情况按参考图排列：16px 已发送人数、12px 目标人数与紧邻的蓝色百分比；下方使用 4px 蓝色圆角进度条和浅灰轨道，注释行显示未发送人数及部署时区的 `YYYY-MM-DD 结束`。发送进度下同时展示已发送、无法发送、待发送；错误仅用文字表示历史错误存在性。窄屏使用 mobile-cards，操作按钮换行排列，不压缩统计字号。原型决策：`codex/prototype-campaign-stats@d08a1093`。

## 视觉令牌

令牌实现位于 `frontend/src/assets/styles/_variables.scss` 的 Sass 变量和 `:root` 自定义属性。页面局部样式优先引用 `--lm-*`，不重复写颜色和阴影。

| 类别 | 规范 |
| --- | --- |
| 字体 | Inter；正文 14px，辅助文字 12px，页面标题 24px，区块标题 18px |
| 间距 | `--lm-space-*`：4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 中性色 | `--lm-neutral-0/50/100/200/300/500/700/900`；页面使用语义别名，不直接引用色阶值 |
| 画布 | `--lm-color-canvas`，用于应用背景 |
| 表面 | `--lm-color-surface`，用于导航、表格、表单容器 |
| 边框 | 普通 `--lm-color-border`，强调 `--lm-color-border-strong` |
| 主色 | `--lm-color-primary`；只用于主操作、链接、选中和焦点 |
| 状态色 | success / warning / danger；状态标签必须同时有文字，不依赖颜色单独表达 |
| 圆角 | 小控件 4px，输入、按钮、工作区 6px；禁止超过 8px 的卡片圆角 |
| 阴影 | 默认 `--lm-shadow-sm`；浮层使用 `--lm-shadow-md`；不使用装饰性渐变或光晕 |
| 焦点 | `--lm-focus-ring`，键盘焦点必须可见 |

## 布局和导航

- 顶部导航固定 64px，移动端 56px；左侧导航宽 248px，使用右侧边框分隔。
- 主内容区使用 `32px` 垂直内边距和响应式水平内边距；页面背景与内容表面分离。
- 一级页面使用 `.page-header`：左侧标题和上下文，右侧主操作；移动端改为纵向堆叠。
- 当前导航项使用浅主色背景与文字强调，不使用竖线；悬停只改变背景和文字，不移动布局。
- 工作区切换、刷新、账号菜单保持在顶部右侧；图标按钮必须有 `aria-label` 和 tooltip。

## 页面和组件

- 页面只保留一个 `h1`；区块标题使用 `h2/h3`，不要用字号代替语义层级。
- 主按钮只保留一个视觉主次；危险动作统一使用 `is-danger`，确认文案必须包含对象或数量。
- 表单控件高度默认为 40px，小型工具控件 32px；常规单行输入最大宽度 560px，窄屏占满可用宽度；标签使用 14px、600 字重。
- 输入框、选择器外层与输入本身使用相同的宽度边界；下拉箭头、图标和计数留在控件边界内。扩展搜索输入继续占满工具栏剩余空间。
- 表格表头使用 15px、700 字重，明显强于 14px 正文；行高 44-48px；可排序表头必须显示可操作反馈。
- 列表空态说明“当前范围没有数据”并提供下一步；加载失败显示重试入口，不用永久遮罩代替错误态。
- 多类受众使用可搜索的分组树选择：分组只负责展开，叶子节点多选并回显；权限和范围沿用后端校验。状态范围较少时使用有可访问名称的下拉筛选。
- 公海列表按来源公海 → 组织分配显示可折叠层级，提供组织、类型下拉及名称搜索。筛选命中的子项保留可读父项作为上下文，父项不计入匹配数且不可批量选择；分页不能拆散分组。来源不在当前可见范围时明确提示，不额外请求越权元数据。
- 营销活动配置按“基本信息、收件客户、发件与回信、发送安排”分组：桌面使用双栏，窄屏按该顺序堆叠；收件选择先于回信配置。发件邮箱仅显示一次，限速/恢复控件集中展示，详细规则与标签/渠道/邮件头可展开。新建时显示下一步编辑内容的提示，测试发送仅在保存后显示。公海的回信优先级比较“列表回信邮箱”和“组织回信邮箱”，列表地址仍取每条导入记录的回信邮箱字段。
- 新建活动的主动作明确为“保存并编辑内容”，保存前置说明靠近页签，只出现一次。用户更改输入后离页须可取消，默认焦点在取消；空白新建态不提醒。此机制不提供刷新后的草稿恢复。
- 无数据时不绘制占位饼图；真实零值与缺失值分别展示。内容格式标签使用中性色，红色留给危险操作与错误状态。
- 日期保持完整；日期加时间可在两者之间分行，不把年月日拆开。只读代码沿用可读的14px主题和深色语法颜色，不因只读整体降低透明度。
- 信息提示使用左侧状态边框和简短标题；不要用大面积高饱和色块承载普通信息。
- 模态框必须有标题、明确的取消操作和合适的 ARIA role；危险确认默认把焦点放在取消。
- 客户列表删除先确认列表，再弹窗选择取消、仅删除列表或同时删除对应客户；第二步焦点在取消，无客户删除权限时禁用对应选择并说明原因。共享其他列表的客户保留，提交中禁止重复操作，失败保留选择以便重试。来源：`frontend/src/views/CustomerLists.vue`。

## 响应式规则

- 768px 以下隐藏桌面侧栏，导航进入顶部菜单，页面内边距降为 16px。
- 表格优先使用 Buefy `mobile-cards`；确需保留表格时必须包在横向滚动容器中，并保证首列和操作列可识别。
- `.page-header`、工具栏和表单布局在窄屏纵向排列；按钮不应被压缩到不可读。
- 不使用固定 `min-width` 撑破视口；固定宽度只允许用于图标按钮、头像和格式化数据列。

## 可访问性验收

- 分页统一使用 `AppPagination`（Buefy 表格通过 `PaginatedTable` 接入），提供每页条数和带名称的页码输入框；上下分页状态同步，条数变化回第一页但不清筛选。有结果的单页仍显示设置，零结果隐藏无效分页；窄屏控件可换行，公海列表按完整父子分组分页。
- 分页工具栏标签、数字、输入及按钮统一使用 `--lm-font-size-toolbar`（13px），控件高度使用 `--lm-control-height-sm`（32px）、圆角 6px；样式集中在 `styles/components/_pagination.scss`。导出操作与分页垂直居中，桌面空间不足时整组换行，手机按组换行；保持原有字体、浅色边框和可见键盘焦点，不使用缩小字号容纳控件。
- 键盘 Tab 顺序与视觉顺序一致，焦点环不能被 `outline: none` 隐藏。
- 图标按钮、分页、搜索、复制、切换和关闭控件都有可访问名称。
- 正文与背景对比度至少 4.5:1；大字号至少 3:1；状态同时提供文字或图标。
- 错误文本关联到对应控件；异步提交有 loading 和 disabled 两种状态。
- 触摸目标不小于 32px，常用行内动作不小于 24px。

日期展示不包含星期。中文界面使用 `YYYY年MM月DD日`，需要时间时使用 `YYYY年MM月DD日 HH:mm`；日志原文保留原始时间戳以便排障。

中文术语统一为“仪表盘”“公海客户”“所属组织”“回信邮箱”“发件邮箱组”；面向订阅者使用“订阅内容”“历史邮件”，不暴露私域客户列表等管理术语。说明只保留用途、输入限制、范围和生效条件；占位符已有相同说明时不重复。字段来源与权限边界不能为缩短文案而删掉。

占位符只写示例、格式、搜索范围或选择提示，不重复字段标签和字段下方的说明。输入框用“例如：……”或可直接照填的格式示例，搜索框写明可搜索的字段，下拉框用“请选择……”，密码框写长度限制或留空规则。示例邮箱统一用 `name@example.com`，域名用 `example.com` 或 `yoursite.com`，不得写入真实路径、主机、邮箱或个人信息。

## 代码约束

- 新页面先复用 Buefy/Bulma 组件和全局令牌，再添加局部样式。
- 样式入口为 `frontend/src/assets/style.scss`；新基础规则写入 `styles/_base.scss`，应用骨架写入 `styles/_layout.scss`，组件覆写写入 `styles/components/`，页面样式写入 `styles/views/`。原 `style.scss` 的旧业务规则逐步迁移，避免新规则继续堆叠在文件末尾。
- 禁止在视图中新增品牌颜色、阴影、圆角和断点的裸值；需要新令牌时先补充本文件和 `styles/_variables.scss`。
- 修改共享样式后运行 `cd frontend && yarn lint && yarn build`，并在 1440px 与 390px 宽度检查标题、表格、表单和弹窗。

当前仪表盘 API 只返回总量和时间序列，没有“上一周期”基准；指标卡不显示推测的增长率。深色模式需要覆盖现有 Buefy 组件与旧视图规则后再开放切换，目前只使用 CSS 自定义属性作为迁移基础。
