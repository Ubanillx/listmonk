# 管理端 UI 设计规范

版本：2026-09-29
适用范围：`frontend/src` 的 Vue 2 + Buefy/Bulma 管理端

这份规范把管理端的视觉和交互决策固化为可检查的规则。页面优先服务于高频运营工作：快速扫描、批量处理、明确反馈和可恢复操作。

## 设计原则

1. **信息优先**：页面标题、当前工作区、主操作和数据状态在首屏建立清晰层级。
2. **克制而一致**：使用中性画布和白色工作区表面，颜色只表达品牌、状态和风险。
3. **可预测操作**：相同动作使用相同位置、图标、文案、加载态和确认方式。
4. **渐进响应式**：桌面端保证扫描密度，窄屏端优先保证操作可达和内容不被裁切。
5. **可访问默认开启**：键盘焦点、可访问名称、对比度、错误提示和状态反馈属于完成标准。

## 视觉令牌

令牌实现位于 `frontend/src/assets/styles/_variables.scss` 的 Sass 变量和 `:root` 自定义属性。页面局部样式优先引用 `--lm-*`，不重复写颜色和阴影。

| 类别 | 规范 |
| --- | --- |
| 字体 | Inter；正文 14px，辅助文字 12px，页面标题 24px，区块标题 18px |
| 间距 | `--lm-space-*`：4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 中性色 | `--lm-neutral-0/50/100/200/300/500/700/900`；页面使用语义别名，不直接引用色阶值 |
| 画布 | `--lm-color-canvas`，用于应用背景 |
| 表面 | `--lm-color-surface`，用于导航、表格、表单容器 |
| 边框 | 普通 `--lm-color-border`，强调 `--lm-color-border-strong` |
| 主色 | `--lm-color-primary`；只用于主操作、链接、选中和焦点 |
| 状态色 | success / warning / danger；状态标签必须同时有文字，不依赖颜色单独表达 |
| 圆角 | 小控件 4px，输入、按钮、工作区 6px；禁止超过 8px 的卡片圆角 |
| 阴影 | 默认 `--lm-shadow-sm`；浮层使用 `--lm-shadow-md`；不使用装饰性渐变或光晕 |
| 焦点 | `--lm-focus-ring`，键盘焦点必须可见 |

## 布局和导航

- 顶部导航固定 64px，移动端 56px；左侧导航宽 248px，使用右侧边框分隔。
- 主内容区使用 `32px` 垂直内边距和响应式水平内边距；页面背景与内容表面分离。
- 一级页面使用 `.page-header`：左侧标题和上下文，右侧主操作；移动端改为纵向堆叠。
- 当前导航项使用浅主色背景与文字强调，不使用竖线；悬停只改变背景和文字，不移动布局。
- 工作区切换、刷新、账号菜单保持在顶部右侧；图标按钮必须有 `aria-label` 和 tooltip。

## 页面和组件

- 页面只保留一个 `h1`；区块标题使用 `h2/h3`，不要用字号代替语义层级。
- 主按钮只保留一个视觉主次；危险动作统一使用 `is-danger`，确认文案必须包含对象或数量。
- 表单控件高度默认为 40px，小型工具控件 32px；常规单行输入最大宽度 560px，窄屏占满可用宽度；标签使用 14px、600 字重。
- 表格表头使用 15px、700 字重，明显强于 14px 正文；行高 44-48px；可排序表头必须显示可操作反馈。
- 列表空态说明“当前范围没有数据”并提供下一步；加载失败显示重试入口，不用永久遮罩代替错误态。
- 多类受众使用可搜索的分组树选择：分组只负责展开，叶子节点多选并回显；权限和范围沿用后端校验。状态范围较少时使用有可访问名称的下拉筛选。
- 营销活动配置按“基本信息、收件客户、发件与回信、发送安排”分组：桌面使用双栏，窄屏按该顺序堆叠；收件选择先于回信配置。发件邮箱仅显示一次，限速/恢复控件集中展示，详细规则与标签/渠道/邮件头可展开。新建时显示下一步编辑内容的提示，测试发送仅在保存后显示。公海的回信优先级比较“列表回信邮箱”和“组织回信邮箱”，列表地址仍取每条导入记录的回信邮箱字段。
- 信息提示使用左侧状态边框和简短标题；不要用大面积高饱和色块承载普通信息。
- 模态框必须有标题、明确的取消操作和合适的 ARIA role；危险确认默认把焦点放在取消。

## 响应式规则

- 768px 以下隐藏桌面侧栏，导航进入顶部菜单，页面内边距降为 16px。
- 表格优先使用 Buefy `mobile-cards`；确需保留表格时必须包在横向滚动容器中，并保证首列和操作列可识别。
- `.page-header`、工具栏和表单布局在窄屏纵向排列；按钮不应被压缩到不可读。
- 不使用固定 `min-width` 撑破视口；固定宽度只允许用于图标按钮、头像和格式化数据列。

## 可访问性验收

- 键盘 Tab 顺序与视觉顺序一致，焦点环不能被 `outline: none` 隐藏。
- 图标按钮、分页、搜索、复制、切换和关闭控件都有可访问名称。
- 正文与背景对比度至少 4.5:1；大字号至少 3:1；状态同时提供文字或图标。
- 错误文本关联到对应控件；异步提交有 loading 和 disabled 两种状态。
- 触摸目标不小于 32px，常用行内动作不小于 24px。

日期展示不包含星期。中文界面使用 `YYYY年MM月DD日`，需要时间时使用 `YYYY年MM月DD日 HH:mm`；日志原文保留原始时间戳以便排障。

## 代码约束

- 新页面先复用 Buefy/Bulma 组件和全局令牌，再添加局部样式。
- 样式入口为 `frontend/src/assets/style.scss`；新基础规则写入 `styles/_base.scss`，应用骨架写入 `styles/_layout.scss`，组件覆写写入 `styles/components/`，页面样式写入 `styles/views/`。原 `style.scss` 的旧业务规则逐步迁移，避免新规则继续堆叠在文件末尾。
- 禁止在视图中新增品牌颜色、阴影、圆角和断点的裸值；需要新令牌时先补充本文件和 `styles/_variables.scss`。
- 修改共享样式后运行 `cd frontend && yarn lint && yarn build`，并在 1440px 与 390px 宽度检查标题、表格、表单和弹窗。

当前仪表盘 API 只返回总量和时间序列，没有“上一周期”基准；指标卡不显示推测的增长率。深色模式需要覆盖现有 Buefy 组件与旧视图规则后再开放切换，目前只使用 CSS 自定义属性作为迁移基础。
